Masonry Layout

Experimental

Native Pinterest-style masonry layout via grid-template-rows: masonry (or grid-template-columns: masonry). Items pack tightly into the available space based on content height — no JavaScript layout library needed.

Safari TP Firefox Flag Chrome Flag Edge No
CSS
/* Option A — masonry on rows */
.gallery {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  grid-template-rows: masonry;
  gap: 1rem;
}

/* Option B — masonry on columns */
.gallery {
  display: grid;
  grid-template-columns: masonry;
  grid-template-rows: repeat(auto-fill, minmax(80px, auto));
  gap: 1rem;
}

/* Progressive enhancement */
@supports (grid-template-rows: masonry) {
  .gallery {
    grid-template-rows: masonry;
  }
}

/* Fallback — CSS columns (close approximation) */
.gallery {
  columns: 3;
  gap: 1rem;
}

reading-flow

Chrome 133+

reading-flow controls the keyboard tab and screen reader navigation order of flex and grid children. Essential for visually reordered layouts (reverse columns, dense grids) where DOM order and visual order diverge.

Chrome 133+ Firefox No Safari No
CSS
/* Flex nav reversed visually */
.flex-nav {
  display: flex;
  flex-direction: row-reverse;

  /* Without this: Tab goes right-to-left (wrong!) */
  reading-flow: flex-visual;
  /* Now Tab follows visual left-to-right order */
}

/* Grid with dense fill */
.grid-layout {
  display: grid;
  grid-auto-flow: dense;
  reading-flow: grid-rows;
  /* Tabs row-by-row, matching visual reading */
}

/* Values:
   normal         — follows DOM order (default)
   flex-visual    — follows visual flex order
   flex-flow      — follows flex-flow direction
   grid-rows      — row-by-row visual order
   grid-columns   — column-by-column visual order
   grid-order     — follows CSS order property
*/
The accessibility problem it solves

When CSS order or flex-direction: row-reverse reorders items visually, keyboard Tab still follows the DOM order — the wrong way around for screen readers and keyboard users.


reading-flow: flex-visual makes the browser sync Tab order to the visual layout automatically — no manual tabindex juggling.

Gap Decorations

Proposal

Style the gaps between grid and flex tracks with decorative lines, dashes, or gradients — using column-gap-rule and row-gap-rule (analogous to column-rule) — without any extra DOM elements.

Not yet Not yet Not yet
CSS (Proposed)
/* Proposed syntax */
.grid {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 2rem;

  /* Horizontal dividers between rows */
  row-gap-rule: 1px solid #1e2e4a;

  /* Vertical dividers between columns */
  column-gap-rule: 1px dashed #2a4070;

  /* Gradient dividers */
  column-gap-rule: 1px solid
    linear-gradient(to bottom, transparent, #5b8dee, transparent);
}

/* Existing workaround (ugly) */
.grid-item + .grid-item {
  border-left: 1px solid #1e2e4a;
}
/* ↑ breaks on row wrapping — gap-rule fixes this */

CSS if()

Chrome Flag

if() brings inline conditional logic directly into CSS property values. Test style queries, custom properties, media conditions, and supports queries — then return different values based on the result, without JS or separate class names.

Chrome Canary Not yet Not yet
CSS (Experimental)
/* Inline conditional on a custom property */
.button {
  background: if(
    style(--variant: primary): var(--accent);
    style(--variant: danger):  #f4456b;
    else: var(--bg-elevated)
  );
}

/* Media-query inline conditional */
.hero-title {
  font-size: if(
    media(width >= 1024px): 4rem;
    media(width >= 768px):  2.8rem;
    else: 2rem
  );
}

/* Supports conditional */
.element {
  display: if(
    supports(display: grid): grid;
    else: flex
  );
}

/* Multiple conditions, single property */
.card {
  border-radius: if(
    style(--shape: pill): 99px;
    style(--shape: sharp): 0;
    else: 12px
  );
}
Why it matters

Today you need a separate class or custom property trick for each visual variant. With if(), a single element can carry its own conditional styling based on state, environment, or data-attributes.


Replaces many patterns that currently need: JavaScript class toggling, complex :not()/:has() chains, or redundant utility classes.

The if() syntax is still evolving in the CSS WG. The exact syntax shown above may change before finalizing.

CSS Mixins (@mixin / @apply)

Spec Draft

Define reusable blocks of declarations with @mixin --name { … } and apply them with @apply --name. Like Sass/SCSS mixins, but fully native CSS — no build step, no preprocessor.

Not yet Not yet Not yet
CSS (Proposed)
/* Define a mixin */
@mixin --center {
  display: flex;
  align-items: center;
  justify-content: center;
}

@mixin --truncate {
  overflow: hidden;
  white-space: nowrap;
  text-overflow: ellipsis;
}

/* Mixin with parameters (proposed) */
@mixin --card-shadow(--blur: 20px, --color: black) {
  box-shadow: 0 8px var(--blur) var(--color);
}

/* Apply mixins */
.icon-container {
  @apply --center;
  width: 48px;
  height: 48px;
}

.card-title {
  @apply --truncate;
  max-width: 200px;
}

.card {
  @apply --card-shadow(40px, rgba(0,0,0,.5));
}
SCSS equivalent today

This is the native CSS equivalent of what Sass/SCSS developers have relied on for 15+ years. The key benefit: no build step. Browser-native mixins mean design tokens and component patterns can be expressed directly in plain CSS files.

Typed attr()

Chrome 133+

The upgraded attr() function reads HTML attributes directly in CSS with type conversion — not just for content, but for any CSS property. Pass data from HTML to CSS without JavaScript bridges.

Chrome 133+ Firefox Flag Not yet
HTML + CSS
/* HTML: 
 */
.grid {
  /* attr(name type, fallback) */
  grid-template-columns:
    repeat(attr(data-columns integer, 3), 1fr);
}

/* HTML: 
  •  */
.swatch {
  background: attr(data-color color, gray);
}

/* HTML: 
     */
.icon {
  font-size: attr(data-size rem, 1rem);
  /* Reads data-size as a rem length */
}

/* Type validation with type() */
[scroll-snap] {
  scroll-snap-align:
    attr(scroll-snap type(start | center | end), none);
  /* Invalid values fall back gracefully */
}

/* Old attr() — content property only */
.tooltip::before {
  content: attr(data-tip); /* Still works */
}

    sibling-index() & sibling-count()

    Chrome / Safari

    sibling-index() returns an element's 1-based position among its siblings. sibling-count() returns the total number of siblings. Together they unlock staggered animations, dynamic sizing, and conditional styling — zero JavaScript counters.

    Chrome 131+ Safari 18.2+ Firefox Flag
    CSS
    /* Staggered animation — no nth-child hacks */
.list-item {
  animation: slide-in 0.4s ease both;
  animation-delay: calc(sibling-index() * 80ms);
}

/* Dynamic width based on position */
.progress-step {
  width: calc(sibling-index() / sibling-count() * 100%);
}

/* Hue rotation per item */
.color-swatch {
  background: oklch(60% .22
    calc(sibling-index() * (360 / sibling-count()) * 1deg)
  );
}

/* Reverse stagger */
.card {
  animation-delay: calc(
    (sibling-count() - sibling-index()) * 60ms
  );
}

@keyframes slide-in {
  from { opacity: 0; translate: 0 20px; }
  to   { opacity: 1; translate: 0 0; }
}
    Staggered items demo
    Item 1 — delay: 80ms
    Item 2 — delay: 160ms
    Item 3 — delay: 240ms
    Item 4 — delay: 320ms

    Delays set via JS here; with sibling-index() it's pure CSS.

    random()

    Spec Draft

    The random() CSS function returns a random numeric value within a specified range. Enables organic, randomized layouts and animations entirely in CSS — no JavaScript Math.random() required.

    Not yet Not yet Not yet
    CSS (Proposed)
    /* random(min, max) */
.particle {
  /* Random position between 0% and 100% */
  left: random(0%, 100%);
  top: random(0%, 100%);

  /* Random delay for organic feel */
  animation-delay: random(0s, 3s);

  /* Random size */
  width: random(8px, 24px);
  height: random(8px, 24px);
}

/* "per-element" keyword — different value per element */
.tag {
  font-size: random(0.85rem, 1.2rem, per-element);
  opacity: random(0.6, 1, per-element);
}

/* "cached" keyword — same value used in multiple props */
.shape {
  --r: random(20px, 80px, cached);
  width: var(--r);
  height: var(--r); /* same random value as width */
}
    What it replaces

    Currently, randomized CSS requires either inline styles set by JavaScript, or hacky workarounds like different nth-child() offsets. With random(), particle effects, generative backgrounds, and staggered organic animations become a CSS-only concern.

    contrast-color()

    Chrome 147 Beta

    contrast-color(bg) automatically returns black or white — whichever provides the highest WCAG AA contrast ratio against the given background color. Accessible color pairs with zero manual checking.

    Chrome 147 Beta Not yet Not yet
    CSS
    /* Auto text color for any background */
.button {
  --bg: var(--brand-color);
  background: var(--bg);
  color: contrast-color(var(--bg));
  /* Returns black or white automatically */
}

/* Works with any color function */
.badge {
  background: oklch(70% .2 200);
  color: contrast-color(oklch(70% .2 200));
}

/* Dynamic theme colors */
[data-theme] {
  --surface: attr(data-color color, #333);
  background: var(--surface);
  color: contrast-color(var(--surface));
}

/* Today's workaround — manual and error-prone */
.button-light { background: #fff; color: #000; }
.button-dark  { background: #000; color: #fff; }
/* ↑ contrast-color() replaces this entirely */

    text-box-trim & leading-trim

    Safari 18+

    text-box-trim (formerly leading-trim) removes the invisible whitespace that font metrics add above and below text. Enables true optical centering and pixel-perfect vertical alignment without magic number hacks.

    Safari 18+ Chrome Canary Not yet
    CSS
    /* New property (text-box-trim) */
.heading {
  text-box-trim: both;
  /* Removes cap-height gap above and baseline gap below */
}

/* Individual control */
.button-label {
  text-box-trim: trim-start;  /* top only */
  text-box-edge: cap alphabetic;
}

/* Perfect vertical centering of text in buttons */
.btn {
  display: flex;
  align-items: center;
  padding-block: 12px;
  text-box-trim: both;
  /* Before: looked off-center due to font descenders */
  /* After:  optically perfect */
}

/* Old workaround — fragile, font-specific */
.btn {
  padding-top: 14px;  /* magic number for Syne font */
  padding-bottom: 10px;
}

    CSS Carousels — ::scroll-button & ::scroll-marker

    Chrome Only

    Two new CSS pseudo-elements bring fully native, accessible carousels — no JavaScript library needed. ::scroll-button() generates navigation arrows, and ::scroll-marker generates dot indicators that sync automatically with scroll position.

    Chrome 135+ Not yet Not yet
    CSS
    .carousel {
  overflow-x: auto;
  scroll-snap-type: x mandatory;
  scroll-behavior: smooth;
}

.carousel-item {
  scroll-snap-align: start;
}

/* Navigation arrows — auto-generated by browser */
.carousel::scroll-button(inline-start) { content: "←"; }
.carousel::scroll-button(inline-end)   { content: "→"; }

/* Accessible labels */
.carousel::scroll-button(inline-start) {
  content: "Previous slide" / "←";
}

/* Style the arrows */
.carousel::scroll-button(*) {
  background: var(--bg-card);
  border: 1px solid var(--border);
  color: var(--text-1);
  padding: .5rem .75rem;
  border-radius: 8px;
  cursor: pointer;
}

/* Dot indicators — auto-generated per snap target */
.carousel::scroll-marker-group {
  display: flex;
  gap: .5rem;
  justify-content: center;
  margin-top: .75rem;
}

.carousel-item::scroll-marker {
  content: "";
  width: 8px; height: 8px;
  border-radius: 50%;
  background: var(--border-glow);
}

/* Active dot — browser handles syncing */
.carousel-item::scroll-marker:target-current {
  background: var(--accent);
}
    What this replaces

    Today every carousel needs: JavaScript for prev/next button logic, JavaScript for tracking active slide and syncing dots, ARIA attribute management, and keyboard event listeners. All of that becomes browser-native with these two pseudo-elements.


    Try it in Chrome 135+ — the demo works natively there.

    scroll-state() Container Queries

    Chrome 133+

    Use container-type: scroll-state combined with @container scroll-state() to style elements based on whether their scroll container is stuck (sticky element at edge), snapped, or overflowing. No scroll event listeners, no JS.

    Chrome 133+ Not yet Not yet
    CSS
    /* "Stuck" sticky header — no JS IntersectionObserver */
.header-wrap {
  container-type: scroll-state;
}

.header {
  position: sticky;
  top: 0;
  transition: box-shadow .2s, background .2s;
}

@container scroll-state(stuck: top) {
  .header {
    background: rgba(7, 12, 24, .95);
    backdrop-filter: blur(16px);
    box-shadow: 0 4px 20px rgba(0,0,0,.4);
  }
}

/* Snap state — style current snap target */
.scroll-container {
  container-type: scroll-state;
  overflow-x: auto;
  scroll-snap-type: x mandatory;
}

@container scroll-state(snapped: x) {
  .snap-item {
    opacity: 1;
    scale: 1;
  }
}

/* Not currently snapped */
.snap-item {
  opacity: .6;
  scale: .95;
  transition: opacity .3s, scale .3s;
}
    Stuck detection — the JS-free solution

    Detecting when a position: sticky element is "stuck" currently requires an IntersectionObserver sentinel trick in JavaScript — a well-known hack.


    scroll-state(stuck: top) makes this a native CSS query — the browser tells the stylesheet when the element has stuck, automatically.

    Cross-Document View Transitions

    Chrome 126+

    Extend View Transitions to work across full page navigations (MPA) — not just SPA same-document updates. Add @view-transition { navigation: auto } to both pages to get animated transitions between any two same-origin pages.

    Chrome 126+ Firefox Flag Not yet
    CSS
    /* Add to BOTH pages (same origin) */
@view-transition {
  navigation: auto;
}

/* Customize the transition */
::view-transition-old(root) {
  animation: 300ms ease-out slide-out-left;
}
::view-transition-new(root) {
  animation: 300ms ease-in slide-in-right;
}

@keyframes slide-out-left {
  to { translate: -100% 0; opacity: 0; }
}
@keyframes slide-in-right {
  from { translate: 100% 0; opacity: 0; }
}

/* Named element transition across pages */
/* Page A and Page B both set this */
.hero-image {
  view-transition-name: hero;
}
/* Browser morphs the element between pages! */

/* Types for different transition directions */
html:active-view-transition-type(back) {
  &::view-transition-old(root) {
    animation-name: slide-out-right;
  }
  &::view-transition-new(root) {
    animation-name: slide-in-left;
  }
}
    MPA animation — no router needed

    Previously, smooth page transitions required a full SPA framework (React Router, Next.js, Astro's View Transitions, etc.). Now two lines of CSS on plain HTML pages is enough for app-like animated navigation.


    Named element transitions are particularly powerful — a product card can morph into the detail page hero with matching geometry automatically.

    This page and index.html both have matching @view-transition { navigation: auto }, so the Back/Forward navigation will animate in Chrome 126+.

    corner-shape

    Chrome 137 Beta

    corner-shape extends border-radius with new geometric corner styles: squircle (Apple-style), bevel, notch, scoop, and more. All using existing border-radius values to control the size.

.app-icon {
  border-radius: 30%;

/* Bevel — straight angled cut */
.sci-fi-card {
  border-radius: 16px;
  corner-shape: bevel;

/* Notch — inward rectangular cut */
.notched-badge {
  border-radius: 8px;
  corner-shape: notch;

.scoop-card {
  border-radius: 20px;
  corner-shape: scoop;

.default {
  border-radius: 12px;
  corner-shape: round; /* default */

.mixed {
  border-radius: 8px 8px 16px 16px;

    field-sizing

    Chrome / Edge

    field-sizing: content makes form controls — especially <textarea> — grow automatically as the user types. No JavaScript ResizeObserver, no hidden mirror element, no scroll-height tricks.

    Chrome 123+ Edge 123+ Not yet Not yet
    CSS
    /* Auto-grow textarea */
textarea {
  field-sizing: content;
  min-height: 2.5rem;
  max-height: 12rem; /* optional cap */
  overflow-y: auto;
  resize: none;
}

/* Auto-shrink input to its content */
input[type="text"] {
  field-sizing: content;
  min-width: 5ch;
}

/* Works on selects too */
select {
  field-sizing: content;
  /* Width adjusts to the selected option */
}

/* Progressive enhancement */
@supports (field-sizing: content) {
  textarea { field-sizing: content; }
}

/* Old JS approach — no longer needed */
textarea.old {
  /* Required: resize observer + JS to set height */
}
    Live demo — type to grow

    Uses field-sizing: content — works natively in Chrome/Edge. JS fallback added for other browsers.

    Firefox and Safari do not yet support field-sizing. Always provide a JS fallback using @supports and a ResizeObserver for cross-browser production use.
